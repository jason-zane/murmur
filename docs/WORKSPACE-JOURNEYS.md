## Provider and prompt architecture boundary

Separate Concourse identity, AI funding/provider connection, and product-service permissions. Capability-aware adapters expose text/streaming/structured output and transcription separately; preserve pending work on quota, never silently use a chargeable fallback. Recipes take a versioned source envelope, requested output schema and explicit uncertainty policy. Treat source content as quoted data; require valid source IDs and references, final completion and lineage checks before accepting output. Human review is still necessary: schema/lineage validation does not prove semantic truth.

`meeting-follow-up/v1`: decisions, proposed actions and uncertain details with evidence IDs; editable subject/body; no guessed addresses. `email-meeting-proposal/v1`: candidate dates/times/zones/participants with quoted evidence, unresolved ambiguity, no calendar write. Per-account settings control suggestions and provider choice; sending/event creation remains separately explicit.

ChatGPT-plan inference is a possible text route, not verified Concourse eligibility. Commercial/remote access needs OpenAI approval; allowance is shared, not unlimited. Audio/transcription requires a separate route. See existing `docs/AI-FOLLOW-THROUGH.md`; no auth, tokens, new credentials, real inference or expanded permissions implemented here.
